# WindAgent AI — финальный UI

Интеграционная сборка A/B/C: [актуальная проверка и ограничения](reports/final-mvp/README.md).
Время запуска теперь берётся из общего расписания; результат общей проверки —
293 Python-теста и две JavaScript-проверки. Описание исходной UI-поставки ниже.

Собран на всех 136 файлах `main` репозитория BAITC-Hacks/hack-9ccceebe-anhalt-any.
Исходный commit: `c43262d632803fe3b11bbfc2c27ba72108decdbc`.
Дизайн и четыре фотографии взяты из переданной папки `hackalem_ui_v5`.

## Запуск

Из корня проекта, Python 3.10+:

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python scripts/run_ui.py
```

Адрес: http://127.0.0.1:8000/ui/. Другой порт: `python scripts/run_ui.py --port 8080`.
Достаточно Python-зависимостей проекта; Node.js для запуска интерфейса не нужен.

## Что готово

- Тёмный адаптивный интерфейс на основе присланного макета: фотографии, обзор, турбины, график, качество данных, этапы обработки и рекомендации.
- Прямое подключение к Python API; frontend не генерирует численные прогнозы.
- Выбор 24/48 часов, даты, источника и турбины. Фильтр T1/T2 меняет показатели, график и CSV.
- График с мышью, касанием и клавиатурой: стрелки, Home/End. На телефоне подписи подстраиваются под ширину.
- Экспорт CSV и исходного JSON с режимом, единицами и происхождением данных.
- Состояния ожидания, расчёта, ошибки, недоступности и неполного результата; таймаут запроса 60 секунд; защита от устаревших ответов.
- Мощность показывается в МВт, энергия в МВт·ч. Пропуски не подменяются нулями. Неполный/некорректный период не получает выдуманную сумму энергии.
- Тексты API отображаются как текст, без исполнения HTML.

## Режимы

**Прогноз ВЭС T1/T2** открывается по умолчанию. Это существующий строгий основной сценарий проекта. В текущем main не подтверждён протокол организаторов, не подключены нужные архивные погодные выпуски и целевая модель Goldwind. Интерфейс получает причины через `/readiness` и отключает расчёт, пока данные не готовы. UI не устраняет эти ограничения модели и не подставляет демо вместо основного прогноза.

**Синтетическое демо** использует существующую демонстрационную модель и fixture проекта через отдельный `/demo-forecast`. Проверенная дата — **10.02.2026**, горизонт 24 или 48 часов. На период 24 часа сервер вернул 71,4 МВт·ч для T1+T2, среднюю мощность 2,98 МВт. Это синтетические данные для демонстрации работы, не производственный прогноз. API не меняет глобальный режим и не вызывает OpenAI.

**Реальные данные Kelmarsh** использует существующий `/observed`: дата **08.11.2017**, турбина **Kelmarsh 1**, горизонт 24 часа. Проверено 144 десятиминутных измерения, покрытие 100%, MAE 51,4 кВт и RMSE 71,5 кВт. Это анализ модели по наблюдаемой погоде другой станции, не прогноз будущего и не доказательство качества Goldwind. Исходные ограничения модели и источника доступны в подробностях расчёта. Данные Kelmarsh: Charlie Plumley, Roberta Takeuchi / Cubico Sustainable Investments Ltd, [CC BY 4.0](https://doi.org/10.5281/zenodo.16807551).

В интерфейсе нет фиктивных температуры, давления, процента уверенности, живых статусов турбин или карты ветра. Пейзажи используются как оформление. Численную модель, правила проверки и исходные конфигурации проект сохраняет.

## Основные файлы

- `src/app/web/index.html`, `ui.css`, `app.js`, `assets/` — новый интерфейс.
- `src/api/main.py` — маршруты UI, безопасная конфигурация, явный режим демо.
- `scripts/run_ui.py` — локальный запуск.
- `tests/test_dashboard.py` — API, статические файлы, изоляция демо, блокеры реального прогноза.
- `tests/test_dashboard_data.cjs`, `tests/test_dashboard_state.cjs` — проверка данных и состояния frontend.
- Исходный интерфейс Streamlit и все скрипты/модели из main также находятся в проекте.

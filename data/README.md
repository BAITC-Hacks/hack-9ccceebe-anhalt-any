## Что скачано

- `raw/kelmarsh/Kelmarsh_SCADA_2017_3083.zip`: полный исходный архив 2017 года,
  174604722 bytes; MD5 `c78263ee52ee0e48e2cb4bbaa1ba211a`, совпадает с Zenodo.
- `raw/kelmarsh/Kelmarsh_WT_static.csv`: паспортные данные, MD5 `af3a038f0f7fddfc1608ad0bfc8cf5ba`.
- `raw/kelmarsh/Kelmarsh_WT_dataSignalMapping.csv`: значения сигналов,
  MD5 `ca8fe399ab15ae7111d3214c632efd36`.

Архив содержит измерения и status/events всех шести турбин, без изменений.
Выбран один полный год из коллекции 2016–2024; остальные годы не скачивались.
Для датасета не нужны аккаунт, Kaggle token или NASA API key.
В Git-ветку исходный ZIP размером 174.6 MB не включается; подготовленные CSV,
metadata, модель и отчёты включаются. Восстановить исходники после clone:
`python -m scripts.download_kelmarsh`. Скрипт скачивает только официальные файлы
и проверяет publisher MD5. Затем `python -m scripts.prepare_kelmarsh` повторяет подготовку.

## Подготовленные файлы

`scada.csv`: 311564 строки с timestamp, wind_speed, wind_direction, temperature,
turbine_id, power, rated_power. Измерения с 2017-01-01 00:00 до 2017-12-31 23:50 UTC.
Номинальный шаг 10 минут; после исключения отсутствующих наблюдений есть пропуски во времени.
Ветер в m/s, направление в градусах, температура в °C, мощность в kW.
Шесть Senvion MM92, номинал каждой — 2050 kW, подтверждён static CSV.

Это реальный target **Power (kW)**, а не Potential power, Energy Export или синтетическая кривая.
Температура — наружная у гондолы (Nacelle ambient temperature), не температура внутри гондолы.
В исходных комментариях каждого файла явно указано UTC.
Встречается несогласованность metadata: отдельная mapping-таблица ошибочно указывает kWh для Power,
но колонка самих измерений явно называется Power (kW). Используются единицы заголовка измерений;
mapping сохранён без исправления. В некоторых заголовках исходника повреждён символ градуса;
точные названия и соответствия сохранены в preparation_report.json.

Исходный объём: 315360 строк (52560 на турбину). Исключены 3796 строк без конечного wind_speed
или power; каждая сохранена в `excluded_rows.csv` вместе с причиной.
Среди оставшихся строк 28014 имеют отрицательную мощность, 3400 — выше номинала.
Они **не удалены**. Нулевой/отрицательный power может отражать остановку/потребление;
подтверждение причин требует анализа status/events. Curtailment и простои не фильтровались.
Температура и направление у оставшихся строк заполнены. Интерполяция не применялась.

`holdout.csv` — копия последних 15% уникальных временных отметок, начиная с
2017-11-07 13:10 UTC. Это test-часть scada.csv, а не дополнительный независимый dataset.
В train_model временной split выполняется до fit: эти строки не участвуют в обучении/выборе модели.
Он отражает только конец осени и зиму; годовая out-of-sample оценка потребует дополнительных периодов.

`preparation_report.json`: provenance, mapping, объёмы, пропуски, исключения и единицы.
Повторная подготовка из скачанного архива: `python -m scripts.prepare_kelmarsh` из корня проекта.
Скрипт также создаёт `config.kelmarsh.json`; config.json обновляется только если это незаполненный шаблон.

## Ограничения использования

Подходит для MODE A (наблюдаемый ветер → наблюдаемая мощность).
Архивных weather forecasts здесь нет, MODE B по этим данным оценивать нельзя.
SCADA ветер измеряется у гондолы; NASA weather на другой высоте/разрешении создаёт сдвиг распределения.
Полученная на Kelmarsh модель не подтверждает точность на другой турбине или ветропарке.
Данные предоставлены авторами «как есть», без гарантии качества.
